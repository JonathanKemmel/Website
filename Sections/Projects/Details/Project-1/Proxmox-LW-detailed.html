Proxmox LW - Detailed Guide

Proxmox VE Installation

Write ISO to USB (Windows, Ventoy)

Using Ventoy (one-time setup):

  1. Download and install Ventoy to your USB drive (this will format the drive).
  2. Copy the Proxmox ISO file onto the Ventoy-formatted USB — no further flashing required.
  3. On target hardware, select the USB as boot media and choose the ISO from Ventoy's menu.

Boot Installer

  • Insert the Ventoy/USB drive into the server, enter BIOS/UEFI boot menu and choose the USB device.
  • From Ventoy, pick the Proxmox ISO (or use the dedicated Proxmox installer USB if you flashed one).

Installer Walkthrough

Follow the installer prompts; the key steps and recommended options are below.

Welcome

  • Choose Install Proxmox VE.
  • Accept the license/EULA to continue.

Target Disk

  • Select the disk to install Proxmox VE on.
  • Use Options (if available) to adjust partition sizes and swap. Recommended guidelines:
    • hdsize: use the full disk or sized for your layout.
    • swapsize: match or approximate system RAM if you expect heavy memory pressure.
    • maxroot: leave space for VM/CT data and backups.
    • minfree: reserve a small amount (e.g., 2G) to prevent full-disk conditions.
  • Choose LVM, ZFS or plain partitions according to your needs; ZFS offers builtin snapshots and integrity at higher resource cost.

Region, Password & Network

  • Select country, timezone and keyboard layout.
  • Set a strong root password and a contact email (for alerts).
  • Network: set a hostname (example: pve.example.local), choose DHCP or static addressing — static recommended for servers. Use environment values for IP, netmask (commonly /24), gateway and DNS (router or public DNS like 8.8.8.8).

Confirm & Install

  • Review all settings carefully, then start the installation.
  • When complete, remove the USB and reboot into the installed system.

First Boot

  • Remove the Ventoy/USB drive so the host boots from the installed disk.
  • Log into the local console as root with the password you set during install.

Access Web Interface

From another machine, open a browser to the Proxmox web UI:

https://<your-proxmox-ip>:8006

Log in as root (or an administrative user) to begin configuring VMs, storage and networking.

Post-install Essentials

Update System

apt update && apt full-upgrade -y

Enable No-Subscription Repository (optional)

If you don't use a paid subscription, you can enable the community repository to receive updates:

nano /etc/apt/sources.list
deb http://download.proxmox.com/debian/pve bookworm pve-no-subscription
apt update && apt upgrade -y

Enable NTP

timedatectl set-ntp on

Enable Firewall

pve-firewall enable

Verify Storage

Open the Web GUI → Datacenter → Storage and ensure local storage points to /var/lib/vz (or your chosen path).

Security & Maintenance

Two-Factor Authentication (TOTP)

  1. In the web UI navigate to Datacenter → Permissions → Two Factor and add a TOTP entry.
  2. Pick the user, scan the QR code with an authenticator app and verify the 6-digit code to enable.

Backups

Schedule regular backups in the GUI:

  • Datacenter → Backup → Add
  • Node: select your node, choose dedicated backup storage, schedule (e.g., Mon–Fri 00:00), pick All, compression ZSTD, mode Snapshot, and set retention (e.g., keep 3 weekly).

Routine Maintenance

  • Monthly: apt update && apt full-upgrade -y and review release notes.
  • Consider monitoring, logging and alerting (Prometheus/Grafana, syslog/ELK) for production environments.
  • Use SSH keys and disable password root SSH where practical; enable 2FA for management users.

Hardware Considerations

  • Consider setting static MACs for important VMs and protecting hosts with a UPS to avoid data corruption during power events.
  • Plan storage (ZFS, LVM, Ceph) according to performance, redundancy and RAM requirements.

Useful Commands

  • Update host: apt update && apt full-upgrade -y
  • List VMs: qm list
  • Backup VM: vzdump <vmid> --mode snapshot --compress zstd
  • Restore backup: qmrestore (or vzrestore depending on backup type)

MyDokuWiki — Container Setup (sanitized)

This boxed summary shows a sanitized, non-sensitive workflow for creating an LXC container, installing a web stack and running DokuWiki. Replace placeholder values with your environment-specific names, passwords and IPs.

Create a Container Template

Proxmox GUI → Node → local(pve) → CT Templates. Click Templates, search for an Ubuntu LXC template (for example ubuntu-24.04-standard_...) and download it.

Create LXC Container

Proxmox GUI → Create CT. Recommended example settings:

  • Node: <your-node>
  • Hostname: mydokuwiki
  • Unprivileged: checked (recommended)
  • Template: the downloaded Ubuntu template
  • Root disk: 8 GB; CPU: 1 core; RAM: 512 MB; Swap: 512 MB
  • Network: DHCP or static IP; DNS: automatic or your DNS server

Update & Install Web Stack (inside container)

apt update && apt upgrade -y
apt install apache2 php php-gd php-xml php-json php-mbstring libapache2-mod-php unzip wget nano ufw -y
systemctl enable apache2

Install DokuWiki

cd /tmp
wget https://download.dokuwiki.org/src/dokuwiki/dokuwiki-stable.tgz
tar -xvzf dokuwiki-stable.tgz
mv dokuwiki-* /var/www/dokuwiki
chown -R www-data:www-data /var/www/dokuwiki

Apache Configuration (HTTP)

Create /etc/apache2/sites-available/dokuwiki.conf with a VirtualHost pointing to /var/www/dokuwiki, then enable the site and modules:

a2ensite dokuwiki.conf
a2dissite 000-default.conf
a2enmod rewrite
systemctl reload apache2

Run DokuWiki Installer

Open http://<LXC-IP>/install.php in a browser, complete the installer (wiki name, admin user/password) and then remove the installer:

rm /var/www/dokuwiki/install.php

Optional: Self-signed HTTPS

a2enmod ssl
mkdir -p /etc/apache2/ssl
openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/apache2/ssl/wiki.key -out /etc/apache2/ssl/wiki.crt
a2ensite dokuwiki-ssl.conf
systemctl reload apache2

Browsers will warn for self-signed certs; accept the exception for local use.

Firewall

ufw allow 80,443/tcp
ufw enable
ufw status

Local Backup Script

#!/bin/bash
TIMESTAMP=$(date +%F-%H-%M)
BACKUP_DIR=/root/dokuwiki_backups
mkdir -p $BACKUP_DIR
tar -czf $BACKUP_DIR/dokuwiki-$TIMESTAMP.tar.gz /var/www/dokuwiki /etc/apache2 /etc/ssl 2>/dev/null
find $BACKUP_DIR -type f -mtime +14 -delete

Make the script executable and test it once, then add a cron entry to schedule backups.

Maintenance

  • Update: apt update && apt upgrade -y
  • Restart Apache: systemctl restart apache2
  • View logs: tail -f /var/log/apache2/access.log
  • Check disk: df -h

Optional: Proxmox CT Backup

Use the Proxmox GUI (Datacenter → Backup) to create scheduled CT backups. Choose snapshot mode and ZSTD compression and store backups in dedicated storage.

MyDokuWiki LXC USB Backup Guide

This guide describes how to set up a weekly backup of a MyDokuWiki LXC in Proxmox to a USB stick. The backup is consistent, snapshot-based, and restorable. A restore test is also explained.

Prerequisites

  • Proxmox VE installed
  • MyDokuWiki running in an LXC (e.g., VMID 101)
  • Root access to Proxmox
  • USB stick, empty or ready to format

Step 1 – Prepare the USB Stick

1.1 Identify USB device

lsblk

Note the correct device, e.g., /dev/sdc.

1.2 Format USB stick

mkfs.ext4 /dev/sdc

⚠️ All data on the USB stick will be lost.

1.3 Set label

e2label /dev/sdc USB_WIKI_BACKUP

1.4 Create mount point

mkdir -p /mnt/usb-wiki-backup

Step 2 – Identify MyDokuWiki LXC

List all LXCs:

pct list

Example:

VMID  Status  Name
101   running mydokuwiki

Note the VMID (101).

Step 3 – Test Manual Backup

3.1 Mount USB stick

mount /dev/disk/by-label/USB_WIKI_BACKUP /mnt/usb-wiki-backup

3.2 Backup with vzdump

vzdump 101 --mode snapshot --compress zstd --dumpdir /mnt/usb-wiki-backup

3.3 Verify backup

ls -lh /mnt/usb-wiki-backup

Expected:

vzdump-lxc-101-YYYY_MM_DD-HH_MM_SS.tar.zst

3.4 Unmount USB stick

umount /mnt/usb-wiki-backup

Step 4 – Automation (Cronjob)

4.1 Create script

nano /root/wiki-usb-backup.sh

Content:

#!/bin/bash
set -e

VMID=101
MOUNTPOINT="/mnt/usb-wiki-backup"
DEVICE="/dev/disk/by-label/USB_WIKI_BACKUP"
LOG="/var/log/wiki-usb-backup.log"

echo "==== Backup Start $(date) ====" >> "$LOG"

mount "$DEVICE" "$MOUNTPOINT"

vzdump "$VMID" --mode snapshot --compress zstd --dumpdir "$MOUNTPOINT" >> "$LOG" 2>&1

# Keep only last 4 backups
ls -1t "$MOUNTPOINT"/vzdump-lxc-"$VMID"-*.tar.zst | tail -n +5 | xargs -r rm --

umount "$MOUNTPOINT"

echo "==== Backup End $(date) ====" >> "$LOG"

4.2 Make script executable

chmod +x /root/wiki-usb-backup.sh

4.3 Setup cronjob

crontab -e

Example (Sunday 03:00):

0 3 * * 0 /root/wiki-usb-backup.sh

Step 5 – Restore Test

5.1 Mount USB stick

mount /dev/disk/by-label/USB_WIKI_BACKUP /mnt/usb-wiki-backup

5.2 Create new LXC (e.g., 103)

pct restore 103 /mnt/usb-wiki-backup/vzdump-lxc-101-YYYY_MM_DD-HH_MM_SS.tar.zst --storage local-lvm
  • 103 = new VMID
  • --storage local-lvm = Proxmox storage for rootfs

5.3 Start LXC

pct start 103

5.4 Verify

pct exec 103 -- bash
  • Check MyDokuWiki content
  • Test uploads and user permissions

5.5 Remove test LXC (optional)

pct stop 103
pct destroy 103

Notes / Best Practices

  • Do not keep USB mounted permanently
  • Backup only via Proxmox snapshot + vzdump, never rsync directly from running container
  • Perform restore tests regularly
  • Rotate old backups, e.g., keep last 4 weeks
  • Check backup logs (/var/log/wiki-usb-backup.log)
  • Never overwrite production LXC directly

Summary

  • USB = backup source
  • Proxmox storage = restore target (local-lvm)
  • Script + cronjob = automated weekly backup
  • Restore test = validate on new VMID (e.g., 103)

With this setup, your MyDokuWiki is safe, consistent, and fully restorable.
